# Haunted Toaster BETA Spine Integration Design

## Status

Approved direction: Option A — BETA Spine.

This document translates that direction into the repository's current authority law. `main` remains authoritative. Divergent alpha.9 / Track-0 branches are evidence and source material only; they must not be merged wholesale.

## Goal

Forge one current-main-first Haunted Toaster ancestor that preserves the landed Video/VSPantry and receipt-memory foundations while porting the field-proven alpha.9 creative/runtime capabilities and Track-0 trust repairs as bounded, reviewable slices.

The resulting ancestor is the only branch on which first-BETA behavior work should proceed.

## Why this exists

The repository currently has two useful lineages:

1. current `main`, which owns the newest product authority including Video/VSPantry, receipt-memory foundation, invalid-garment refusal, and the Creative Context Table design;
2. the divergent alpha.9 / Track-0 lineage, which carries Mutation Lattice/Shape Pack/Topology Arc, calibrated visual-language-v3 behavior, Elastic Topology Response, bounded nested-response compilation, and Listener draft durability.

The successful packaged aggressive-lane render is human evidence that the former unbounded FFmpeg/parser failure boundary is no longer universal. The remaining Track-0 human observations — Low & Slow expressive reach, Listener close/reopen durability, and Re-listen anchor preservation — remain witness items; they do not authorize pretending the divergent branch is current authority.

## Governing laws

- Current `main` is product authority.
- Never merge a divergent historical branch wholesale.
- Port only compatible pieces that satisfy current contracts.
- Preserve current-main Video/VSPantry and receipt-memory behavior while porting alpha.9 capabilities.
- Keep accepted `VisualScore -> ResolvedTimeline -> preview -> production render -> receipt` authority unchanged.
- No renderer-local creative improvisation or ambient entropy.
- Historical renderer/profile semantics remain explicit and replayable.
- No BETA candidate-ecology behavior is enabled merely by completing this integration ancestor.
- No release, tag, main merge, or artifact promotion is authorized by this integration slice alone.

## Architecture

### 1. Current-main-first porting

Create the integration branch directly from current `main`.

Port the divergent lineage in dependency order, using the existing regression tests from the proven heads as executable contracts:

```text
current main
  + alpha.9 semantic core / raster-4
  + alpha.9 calibration + renderer identity repairs
  + Elastic Topology Response
  + bounded nested-response compilation
  + Listener close/reopen durability
  + current-main Video/VSPantry regression preservation
  + safe non-renderer beta foundations
      -> one BETA integration ancestor
```

A port may reuse exact source from the historical branch only where the target file is new or its current-main contract is unchanged. Files that now carry current-main behavior — especially candidate/session, renderer UI, preload/IPC, package/version, and build-capability seams — must be reconciled semantically rather than replaced.

### 2. Regression-first port gates

Each historical capability enters by importing its existing tests first and observing a meaningful RED on the current-main-derived integration branch. Production code is then ported minimally until those tests are GREEN while current-main tests remain green.

The important gates are:

- alpha.9 Mutation Lattice / Shape Pack / Topology Arc and raster-4 compatibility;
- calibrated six-up base identity and topology differentiation;
- Elastic Topology Response / nested-response replay;
- bounded nested-response compilation through the real FFmpeg parser;
- Listener draft durability and explicit Re-listen anchor law;
- Video/VSPantry session/IPC/package regression tests;
- receipt-memory foundation regressions.

### 3. Safe beta foundations after runtime convergence

Two existing branches are intentionally suitable to join the ancestor because they do not change production render/generation semantics:

- PR #173 — ToastPack Frame Reservoir v1;
- PR #170 — Creative Context Table / Influence Diet contract foundation.

They may be ported/rebased onto the integration ancestor only after the core runtime convergence is green. They do not authorize Frame Motion execution or context-aware candidate composition yet.

### 4. Explicit boundary after the ancestor

The integration ancestor stops before first-BETA creative interaction changes.

The next independent plans are:

1. #147 candidate ecology: no Toast Feel preselection + exact two-parent CROSS;
2. migrate existing receipt-memory influence behind `memory/receipt-v1` and expose Past Toasts/Re-toast through one authority law;
3. re-anchor #167 Beta Home against the real capability set;
4. neutral-ground/source-reveal and upright-title presentation repairs;
5. only then execute Frame Motion, broader verbs, YouTube transport, HAUNT sibling capsules, and richer Thoughtline.

## Conflict policy

When historical code conflicts with current-main behavior:

1. preserve the current-main public/session/IPC contract;
2. identify the smallest semantic capability the historical code supplied;
3. re-express that capability behind the current-main seam;
4. add or preserve a regression test proving both behaviors coexist;
5. refuse scope expansion if coexistence requires architectural redesign not covered by this slice.

Do not resolve conflicts by taking an entire historical file merely because its tests once passed.

## Build and capability identity

The integration branch must derive capability/build identity from the active renderer/profile and registries. It must not advertise BETA candidate ecology before #147 exists.

Expected integrated runtime identity includes alpha.9/raster-4 capability only when the actual candidate/session path can produce and render it on this current-main ancestor.

## Human field evidence

The packaged integration artifact should preserve the four Track-0 human witness questions:

1. aggressive lane completes without the former giant nested-expression parser failure;
2. Low & Slow retains meaningful full-width expressive reach at climax;
3. close -> reopen keeps exact human Listener timing edits;
4. explicit Re-listen keeps human anchors exact while machine-owned evidence may change.

These verdicts should be captured as witness evidence, not silently converted into machine truth.

## Verification contract

Local/CI proof for the ancestor must include:

```text
npm --prefix src/full-measure ci
npm run verify
npm --prefix src/full-measure test
npm --prefix src/full-measure run smoke
```

Plus repository UI witness where affected, production dependency audit, and GitHub Actions Windows Setup + Portable packaging for the exact PR head.

A packaged Windows human witness remains required because Listener/native Electron behavior and raster-4 rendering are involved.

## Artifact / authority impact

Expected:

- adds/reintroduces raster-4/v3 profile and compatible v3 constraints on the current-main lineage;
- adds canonical nested-response/topology-response evidence to raster-4 timelines and receipts under their versioned policies;
- preserves current-main Video/VSPantry evidence and receipt-memory foundation;
- may add Frame Reservoir and Creative Context Table contract artifacts after convergence;
- does not widen Video/Frame Reservoir into `executionForRender()`;
- does not make Creative Context Table ambient renderer state;
- does not enable #147 or BETA Home capability flags yet.

## Stop condition

Stop the integration slice when one exact-head PR proves:

- current-main Video/VSPantry and memory foundation still work;
- the trusted alpha.9/Track-0 capabilities have been ported through current contracts rather than wholesale history;
- deterministic tests and production smoke are green;
- canonical browser witness is reviewed where changed;
- Windows Setup + Portable artifacts build for that exact head;
- remaining uncertainty is explicitly human field witness rather than unresolved machine integration.

At that point the branch is the selected ancestor for #147.
